# 手感：为什么拳头打得上

写给要改这套东西的人。**一句话题眼：**
「功能都实现了，但我用不起来」几乎从来不是判定太窄，而是**时间没对齐**。

这份文档记录的是一次真实的线上返工——玩家原话是「几乎攻击不上车辆，都是我被
撞飞了；也攻击不到 bot」。武器、伤害、赏金、冷却一样不缺，问题是玩家**够不着**。
下面每一条都先给出量出来的数，再给根因和修法。数字来自
`.blacktop-scratch/lampdrive.mjs`（灯驱探针）与线上 Worker 的 `ATK` 日志。

## 0. 修之前 vs 修之后

| 指标 | 修之前 | 修之后 |
|---|---|---|
| 真人在线按 `J` 的命中率 | 4/51 ≈ **11%** | **69% ~ 83%** |
| 同一个房间里的机器人 | 91% | 91% |
| 「按了，一点回音都没有」占比 | **33%** | 7% |
| 画面里 40 米内的对手 | 无（最近的 150 米外） | dz 0.6 ~ 3.2 米 |
| 服务端入力队列深度 | 稳定 73 ~ 95 格（≈ 1.3 秒） | 0 |

**人和机器人的差别不在手快。** 这是整份文档的出发点。

## 1. 时间账：一次出拳要跨过四段时间

按下 `J` 的那一刻，到服务端把这一下算进世界，中间隔着四段：

1. **插值延迟**（`view.mjs` 的 `INTERP_DELAY = 0.14`）——画面上的一切是 140 毫秒前
   的样子，那 140 毫秒是买"两帧之间能插值"付的钱；
2. **本地预测的领先量**——`predict.mjs` 让我这台车站在"确认点 + 未确认格数"，
   它通常比渲染头还要靠前；
3. **单程网络**（半个 RTT，手机上是 50 ~ 100 毫秒）；
4. **服务端 tick**（60Hz，一格 16.7 毫秒）。

加起来 0.2 ~ 0.3 秒。对向车相对速度 70 m/s，这 0.3 秒就是**二十米**——
玩家瞄准的是一台二十米外的车，判定的却是已经贴到脸上的那一台。

### 四条基于时间的修法

| 修法 | 位置 | 治什么 |
|---|---|---|
| **回看**（`vt` / `cvt`） | `sim/history.mjs` | 让判定退回到玩家看见的那一刻 |
| **判定窗**（0.3 秒） | `sim/combat.mjs` | 让"提前一点按"也兑现 |
| **冷却缓冲**（420 毫秒） | `web/js/input.mjs` | 让冷却中的那一票不被吞 |
| **整幅画只有一个时刻** | `web/js/view.mjs` | 让我、对手、车流画在同一刻 |

## 2. 回看：让判定回到玩家看见的那一刻

客户端在每条上行命令里捎上两个时刻（`cmd.mjs` 的 `flush`）：

- `vt`——我按下时，**人和车手**画在哪个世界时刻；
- `cvt`——我按下时，**车流**画在哪个世界时刻。

为什么是两个而不是一个：车流在画面上被按自己的速度**补到了最新一帧**
（撞车是拿真实位置判的，画得晚就等于"车还在八米外我就飞了"），所以它和人
画的不是同一个时刻。

服务端拿它们去 `history.mjs` 的环形缓冲里翻出那一刻的位姿，用那个坐标做判定，
**伤害、推挤、结算仍然作用在现在的真实实体上**——历史只借来一个坐标。

三条边界（都在 `sim/history.mjs` 里写着）：

1. 只记**位置**。谁是谁、什么状态，历史不负责。
2. 回看有上限 `REWIND_MAX = 0.4` 秒。不封顶的话，改过的客户端可以报一个
   "我还在二十米外"的时刻，然后把早就跑掉的人打下车。
3. **一边缺了就整块作废**。混用"人用历史、车用当下"会让相对位置凭空差出十几米，
   那正是"看着贴上了却打不着"的来源。

## 3. 判定窗：出拳之后 0.3 秒里，每格重判一次

`TUNE.atkWindow = 0.3`。手挥出去之后，如果当场没有目标，这一拳**不作废**——
它挂成 `r.atk = { dir, spec, t }`，接下来每格由 `syncAttack()` 重新算一次
`aimAt()`，谁在这段时间里撞进窗口就吃这一下，兑现一次即消。

为什么是 0.3 而不是更长：它要对齐的是"人的反应时间 + 一点网络抖动"，不是
"让玩家可以闭着眼连按"。对向车穿过 11 米窗口需要 157 毫秒，0.3 秒的窗足够
覆盖它，又不至于让"时机"这件事彻底消失（冷却仍然是 0.5 秒 × 武器系数）。

窗口里的重判一律用**当下**坐标，不走回看。两者回答的不是同一个问题：
回看回答"我按下去的时候屏幕上长什么样"，窗口回答"我这一拳挥出去之后，
路上有没有东西撞上来"——后者本来就发生在现在。

## 4. 冷却缓冲：冷却是限制，不是"你这票不算"

手里的家伙越好，冷却越长（`TUNE.attackCd × spec.cd`）。玩家连按的节奏是均匀的，
必然有一部分落在冷却里，被服务端一句 `attackCd > 0` **直接丢掉**——探针量到
21 次按键里 7 次**完全没有回音**。这不是"你打空了"，是"你按了，游戏没理你"。

修法在 `web/js/input.mjs`：冷却中按下就存进 `S.actWait`（最多 420 毫秒），
`pumpActions()` 每帧检查一次本地预测的 `attackCd`，胳膊一能动立刻兑现。
判据读**本地预测**的冷却，因为它和服务端是同一段代码逐格递减的，两边不会对不上。

## 5. 机器人得跟得上人，否则"人机混战"是句空话

线上日志里有一行很扎眼：开局第 21 秒，真人前面一个对手都没有，十三个机器人
全在他身后 **150 ~ 300 米**。

根因是 `sim/ai.mjs` 的 `makeBrain()` 里那一行：

```js
throttleCap: clamp(r.skill * random(w, 0.9, 1.0), 0.55, 1)   // 旧
```

`skill` 是 0.74 / 0.82 / 0.90，乘上 `[0.9, 1]` 的随机数，等于把机器人的稳态速度
压到了人的 **67% ~ 90%**。速度差 10 m/s 看着不大，但它是**线性累积**的——
差距随时间一路拉开，路上就没有人了。玩家打不着人，不是判定不准。

现在只留 3% 的性格差（`0.88 + skill × 0.12`），快慢交给**反应与走线**去区分；
另外落后 60 米以上的机器人会更舍得捏氮气（`aiInput` 的 `chase`），
那是橡皮筋——它只在后面拉，不在前面踩。

## 6. 积压漏桶：一格一格的延迟线，得让它能自己消

客户端按**真实时间**产格（浏览器卡一下就补几格），消息却是**一坨一坨**到的。
旧规矩"每 tick 只消耗一格"于是留下一条**永不自愈**的延迟线：两边速率一样，
积压永远退不掉。实测队列稳定在 73 ~ 95 格，逼得攻击回看超出 `REWIND_MAX`，
一律 whiff。

现在的规矩在 `sim/netcode.mjs`：

- **每 tick 无条件走一格**（不花额度）——这是"不比真实时间慢"的保证；
- 另外每 tick 攒一格**额度**（`grantCredit`，上限 `CREDIT_MAX = 30`），
  拿来把"卡一下"送来的那一坨吃掉（`spendCredit`，一 tick 最多 `BURST_TICKS = 4` 格）。

长期平均仍然是 1 格/tick，所以**改过的客户端宣称 20 格也跑不成 20 倍速**；
但突发的那一坨能自己消化掉。修完实测队列深度 93 → 0。

## 7. 距离灯：把"够不着"翻译成"往哪边靠"

玩家并排跑在邻道上（车道中心相距 3.6 米）时画面上明明贴着，判定却还差一截。
`web/js/rangelamp.mjs` 把那两块牌子点起来：写「人 / 车 / 牛」表示**现在按就行**，
写「靠左 / 靠右」表示**够不着，但压过去就够得着**。

它有一条铁律：**灯和判定必须是同一段代码**（`sim/combat.mjs` 的 `aimAt`）。
两处各写一份窗口，迟早会漂成"灯亮着却打空"——那比没有灯更伤。
唯一的差别是 `nudgeTarget`（横向放宽一档，只用来点亮"靠过去"）。

## 8. 四条留给后人的不变式

改这套东西之前，先读这四条：

1. **整幅画只有一个时刻。** `view.mjs` 的 `leadTime` 给出它，我、对手、车流、
   畜生全都画在那儿，`vt === cvt` 也是这么来的。谁再单独把某个东西"画得更晚
   一点"，就把判定和画面重新撕开了。
2. **判定与提示同源。** 灯、机器人、真人判定读同一个 `aimAt`。
3. **回看是加分项，不是必需品。** 拿不到历史就退回当下，绝不能只退一半。
4. **手感数字只在 `spec.mjs` 的 `TUNE` 里。** 逻辑里不许出现魔数——调平衡的人
   改的应该是一张表，不是别人的判定分支。

## 9. 踹飞要看得见：往哪飞是构图题，不是物理题

线上原话：「我踢车出去，现在确实成功率高了，但是因为车速快，所以车很快地消失在
画面外了，导致被踢出路边的画面来不及看到。」

根因有两条，都不是"打击判定"的事：

1. **方向错了。** 最早的写法是"顺着它原来的方向继续飞"——对向车本来就朝你冲，
   被踹了还朝你冲。相对速度 ≈ 70 m/s，0.15 秒就滑出画面。
   现在一律朝**路的正方向**飞（`traffic.fling` 里那句 `v.dir = 1`）。
2. **横向给太多了。** 相机挂在踹人的人身后，能看见的横向范围只有 `半屏 ÷ ppm`
   米——车贴到眼前时那只有七米。横移 11~22 米/秒的车半秒就横着出画。那不叫踹飞，
   叫蒸发。现在只给"够把它推出路面"的量：`横向速度 × 一秒半 ≈ 一条半车道`。

留人的那个量是**前向**的：飞出去的速度 = 不慢于踹它的人，**再多 6~12 米/秒**
（轻车多给一点）。它和玩家同向、一路领先，于是那段抛物线、翻滚、落地爆炸全在
画面里；横向那一小分量同时把它挪向路肩，两条轨迹叠起来就是"踹得横过来、翻滚着
摔进路肩"。

实测（探针 `flingscreen.mjs`，玩家 41 m/s、贴脸踹一台轿车）：最后一次出现在画面
里是 **1.50 秒**，改之前是 **0.15 秒**。真游戏里逐帧记一遍（`kicktrace.mjs`）
也是整段都在画面里，落点在屏幕上稳定地待在裁判席那一带，不再"唰"地溜出去。

仪表舱（画面下缘那块板）是同一件事的另一半：它原来 206px 高，屏幕高的四分之一，
把眼前那条路挡掉了一大截，而"被踹飞的车"正是从那里飞出去。现在压到 132px
（屏幕高 14.7%），表盘 118→84、上弧 62→40。**高度是这块板的第一预算**：
表盘、上弧、两栏的间距都按它排，`web-hud-fit.test.mjs` 与 e2e 里那条
"仪表舱只占屏幕下缘那一条"一起守着它。

## 10. 一局三圈：单程冲刺那笔账算错了

原来一局是**单程**：从头跑到尾，冲线就结束。问题的账在"人机混战"上——十五台车
挤在三四公里的路上，第一名冲线时后面还有一半人没过第一个弯，一局就散了。所以
默认改成**三圈**（`sim/track.mjs` 的 `DEFAULT_LAPS`，`length` 仍是一圈的长度，
终点在 `totalLength = length × laps`）。

改一个数字不难，难的是**别让别处继续按一圈说话**。这一轮顺着摸出来的有六处：

1. **路得能接上自己**。四条正弦（两个曲率、两个坡度）的波长全都掐成一圈长度的
   整数分之一，于是 `curveAt(0) === curveAt(length)`、导数也相等——车开到圈末，
   路正好卷回起点。接不上的话，三圈就是同一道折角撞三次。代价是波长最多偏个
   一两成，划算。
2. **路边道具按圈复用**。槽位表只算一圈，`propsBetween` 按世界槽号取模——
   第二、三圈的路边就是第一圈的复制，不会"过了终点路边秃掉"；接缝两槽还得躲开
   同一款道具（不然圈末圈首摆出两座一模一样的井架）。
3. **计时上限与地上的家伙跟着圈数放大**：`TIME_LIMIT_PER_LAP × laps`、
   `MAX_PICKUPS × laps`。不放大，三圈里有一大半人会被"时间到"截胡。
4. **过线要报平安**：`crossFinish` 除了记终点，还推一条 `{ k: "lap", l, n }`——
   客户端拿它播报"跑进第 N 圈"，也才看得到还剩几圈。
5. **HUD 上写着第几圈**（`hud.mjs` 的 `hudLap`），单程的局写"单程 · 到终点"。
6. **终点横幅只有最后一圈才挂**。这是最容易漏的一处：横幅原来画在"一圈的尽头"，
   一圈时代完全等价；改成三圈之后它会在第一圈就朝你招手，然后你还得再骑两圈。
   现在 `web/js/finishline.mjs` 把两件事分开——每圈尽头一条**圈线**（它就是起跑线），
   最后一圈那条额外挂两道横梁。

同一轮里还补了一件事：**鼠标左键 = 正前方一拳**。现代玩家的手就搭在鼠标上，而出拳
是这条路上最吃操作的一下。它和键盘、触屏走**同一条**通道（都归到那个动作位掩码），
所以判定、冷却缓冲、本地预测、上行报文一个都没改——也不可能长出第三套手感。
门槛是三条：只在赛道上生效、只认左键、落在控件（按钮/链接/暂停遮罩）上不算。

## 11. 路面上的车"一顿一顿"：抖的不是车流，是镜头

柠檬叔在第二台电脑上进来，说机器人的画面"卡的像幻灯片，根本不可玩"。查下去发现
跟网络没关系，也跟车流没关系——**车流的世界位置一直是平滑的，抖的是相机**。

账是这样的：本地预测（`predict.mjs`）是**整格**推进的，攒够 1/60 秒才走一格；
而相机严格贴着我这台车的 `z`（`road.mjs` 的 `createCamera`）。60fps 下"一帧一格"
刚刚好；120fps 变成"一格走两帧"，30fps 变成"一帧走两格"。于是**整幅画面**连同
路上所有的车一起，一格一跳。用假时钟量过（`tests/web-subtick.test.mjs`）：
120fps、37.8 m/s 时，我那台车逐帧位移的二阶差分是 **0.63 米**——一格一跳的台阶
就是这么大；社会车辆相对镜头同样是 0.64 米。

修法只有一句：**把"已经过去、还没来得及模拟"的那一小段时间补上**。`app.mjs`
每帧把攒在手里的 `state.acc` 留在 `S.tickAcc` 上，`view.mjs` 按 `v × tickAcc`
把我这台车往前推那半个格子。

两条边界值得单独记住：

- **补的是画面，不是世界**。预测状态一位都不许动——它动一点点，下一次对账
  （`reconcile`）就会把这几个厘米拽回去，画面反而更抖。测试里拿"关掉补帧的
  同一份代码"做对照，逐位比对预测状态。
- **车流也要补到同一个时刻**。`leadTime` 里那半格不能漏：漏了的话，我这一台
  比整条路超前最多一格，38 m/s 下就是 63 厘米——玩家看到的是"眼前那台车在抖"。

同一轮里两件小的，都是"设计做出来了，但玩家用不起来"的那一类：

**挥空要有回音。** 以前挥空只有一声很轻的响，玩家分不清"我打空了"、"我按了但
游戏没理我"、"我方向按反了"三件事。现在自己挥空会在拳够得到的那一截路上弹一个
`MISS`（前打摆身前、回身摆身后），方向对了但没打中一眼就看得出来。别人挥空一个字
都不弹——十五台车每次抡空都飘一行字，画面就成弹幕了。这个事件是 `sim/combat.mjs`
发的，车、牛、人三条路径共用同一次判定，所以字幕天生对三种目标一视同仁。

**名字牌回到头顶。** 原来挂在离地 2.9 米，而车手连人带盔才 1.84 米高——名字飘在
半空，和它下面那个人读起来是两件事。现在是 `render.mjs` 的 `NAME_H = 2.05`，
贴着盔顶一两指头。标签一旦和它的目标脱开，就不再是标签。

## 12. 怎么复测

```powershell
npm test                                          # 350 条，含 sim-laps / web-finishline / web-mouse-attack
                                                  #       / web-subtick / web-miss / web-nameplate
$env:E2E_PLAYWRIGHT_DIR='E:\dev-state\npm-global\node_modules'
npm run e2e                                       # 真浏览器、两个客户端；三圈的局要跑四分钟上下
```

手感本身要靠"灯驱探针"来量——它模拟一个**只看得懂 HUD 那两块牌子**的玩家：
牌子说「人 / 车 / 牛」就按 `J`，说「靠左 / 靠右」就压车，然后统计
「按下去的那些次里有多少真的打中了」。探针在 `.blacktop-scratch/`（不入库）。

| 探针 | 量什么 |
|---|---|
| `lampdrive.mjs` | 只看灯打的命中率、四种结果的分布、每一拳时画面与服务端的几何 |
| `qwatch.mjs` | 入力队列深度、RTT、预测与权威坐标的差、上行格数 |
| `flingscreen.mjs` | 被踹飞的车逐格落在**屏幕第几行第几列**（用渲染层那套相机） |
| `kicktrace.mjs` | 真游戏里逐帧记同一件事：赏金一跳就开始记，直到它烧完 |

**测出来的数才是结论。** 这一轮所有的修法都是先让探针跑出数字，再去改代码的——
改完再跑一遍同一支探针。没有数字的手感改动，就是在猜。
