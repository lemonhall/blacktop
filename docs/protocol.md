# 线协议参考

两份实现（后端 Room DO 与前端）之间唯一的契约。**字段名短到一眼扫完，含义在这里写死。**

改之前先读最后一节「改协议的三条规矩」。

- 传输：HTTP 走控制面（身份、目录、建房、战绩），WebSocket 走对局面。
- 编码：JSON。不是二进制——这个项目的读者首先是架构师，打开 DevTools 就能看懂
  每一帧发了什么，比省下 60% 字节值钱。一帧快照约 4KB（15 台车 + 车流），
  20Hz 下约 80KB/s。
- 单位：长度**米**；对外速度一律**公里/小时**（内部是 m/s，编解码时乘除 `KMH`）；
  时间戳毫秒；世界时间 `tm` 是**秒、带毫秒精度**。

## 1. HTTP

完整的请求时序见 [flow.md](./flow.md)，端点一览在它结尾。这里只记两条契约：

**鉴权**：`Authorization: Bearer <token>` 或 `?token=`（WebSocket 用后者，
因为浏览器没法给 WebSocket 设 header）。令牌载荷 `tenant|playerId|name|exp`，
HMAC-SHA256 签名，有效期 6 小时。

**错误体**：一律 `{ "error": "<机器码>" }`。机器码有：`unknown_tenant`（租户没注册）、
`unknown_room`（这一间散了）、`guest_disabled`、`not_ready`（还有人没举手）、
`join_closed`（房主不许中途加入）、`kicked`、`room_full`、`too_many_rooms`、
`no_room_code`、`forbidden`（密钥不对）、`id_required`。
客户端拿它对文案，**不要**靠 HTTP 状态码猜语义。

## 2. WebSocket 上行（浏览器 → 房间）

| `t` | 字段 | 谁可以发 | 说明 |
|---|---|---|---|
| `ping` | `id` | 任何人 | 心跳（2 秒一次），顺便推世界一格；回 `pong` |
| `bike` | `b` | 任何人 | 选车：0 街霸 400 / 1 暴走 750 / 2 铁马 1200 |
| `ready` | `v` | 非房主 | 举手 / 放下手。房主的举手会被拒（他的"出发"就是表态） |
| `bots` | `n` | 房主 | 机器人数，夹在 `[0, 租户规则.maxBotsPerRoom]` |
| `config` | `mode`, `joinLive` | 房主 | 换赛道（白名单外回落 `city`）、开关中途加入 |
| `kick` | `id` | 房主 | 踢人；被踢者十分钟内进不来 |
| `start` | — | 房主 | 开局。不满足闸门时只回 `error`，不换任何状态 |
| `reset` | — | 房主 | 结算之后回到候场，并清空全体举手状态 |
| `in` | 见下 | 任何人 | 输入命令 |

### 输入命令 `{t:"in"}`

```json
{ "t":"in", "sq":128, "th":1, "br":0, "st":-0.5, "nos":0, "act":0, "n":3 }
```

| 字段 | 含义 |
|---|---|
| `sq` | 命令序号，单调递增。服务端会把小于 `ack` 的顶回去（`max(sq, ack+1)`） |
| `th` `br` | 油门 / 刹车（0/1，摇杆类设备可以给 0~1 的连续值） |
| `st` | 压车：-1 左 … +1 右（客户端量化到 1/16，免得摇杆抖一下就把命令切碎） |
| `nos` | 氮气 0/1，有冷却 |
| `act` | 一次性动作，位掩码：**1 前打（打身前的人，也只有它踢得飞大运）、2 回身打（打身后的人）、4 换家伙（腰里那几件轮着来）**。三个位同时按下时优先级是 **4 > 1 > 2**，"换家伙"永远先落地；出拳的两个位共用同一个 0.5 秒冷却——一帧只挥一次。**只在命令第一格生效**，否则按住会连出好几拳 |
| `n` | **这条命令代表几格**（1 格 = 1/60 秒）：0~20。25Hz 上行时是 2~3，倒数里是 0 |

三条不变式（改动这一层之前先读一遍）：

1. 一条命令只有**一组**入力——操作变了就必须换新命令，否则重放会走形；
   出拳额外强制切一条，不然"这一拳"会被挂到几十毫秒前就已经在走的命令头上。
2. `ack` 单调递增，而且 `ack` 位置是"**那条命令走完那一刻**"的坐标，
   不是"现在的坐标"。
3. 服务端每 tick 最多消耗一格，永远不因为消息来得快就多走——**速度上限靠这个守**。

`n === 0` 的命令不入队（它只是"世界别停"的心跳），客户端也不把它计入待确认列表。

## 3. WebSocket 下行（房间 → 浏览器）

| `t` | 说明 |
|---|---|
| `hello` | 握手后第一帧：`{you:{id,name}, room}` |
| `room` | 名册 / 房间状态的**全量**视图；任何变化都广播给所有人 |
| `begin` | 发车：`{room}`，客户端据此换屏并清掉上一局的残留状态 |
| `map` | 赛道与名册（见下）。开局发一次；**有人补位时给所有人重发一次** |
| `s` | 快照（20Hz） |
| `over` | 结算：`{results}` |
| `pong` | 心跳回应：`{id, now}` |
| `kicked` | 你被请出去了（十分钟内进不来这一间） |
| `error` | `{error, pending?}`；`not_ready` 会带上还没举手的名字 |

### `map`

```json
{ "t":"map", "mode":"city", "seed":113448647, "difficulty":1,
  "lanes":4, "length":3600, "countdown":3.2,
  "roster":[[7,"g_Fhog…","human","柠檬叔",2,3,1], [9,"bot:3","bot","疤脸",0,1,0.87]] }
```

`roster` 每行是 `[车号 id, ownerId, kind, 名字, 车型, 配色, 技能]`。
**发规则而不是发结果**：客户端拿 `seed + mode` 自己算出逐位一致的赛道。

`map` 必须排在快照前面——客户端要靠名册才知道"快照里哪条记录是我"。

### `s`（快照）

```json
{ "t":"s", "tk":1523, "ph":"live", "tm":25.383, "wt":1790703361847, "cd":0,
  "r":[ { "i":7,"x":-3.2,"z":1284.5,"v":183.4,"rk":3,"d":2,"dy":0,"ak":128 } ],
  "tr":[ [31,"van",-6.1,1310.2,1,1,0,0,72] ], "ev":[ { "k":"wreck","i":4 } ] }
```

| 顶层字段 | 含义 |
|---|---|
| `tk` | 世界 tick（单调递增，60Hz 一格） |
| `ph` | `live` / `over` |
| `tm` | **世界模拟时间（秒，三位小数）**，插值就靠它 |
| `wt` | 发送时刻的墙上时间，只给探针与诊断（渲染头用的是本机 `performance.now`） |
| `cd` | 发车倒数剩余秒数；倒数里油门锁死 |

车手 `r[]`：

| 字段 | 含义 | 字段 | 含义 |
|---|---|---|---|
| `i` | 车号（**身份只有这个**） | `rk` | 当前名次 |
| `x` `z` | 位置（米，`z` 是沿路方向） | `fi` `ft` | 是否冲线 / 冲线时刻 |
| `v` | 速度（km/h） | `d` `dy` `cr` | 撂倒 / 踢飞大运 / 摔车 次数 |
| `st` `wk` | 在骑还是在摔（`wk` 是摔车进度） | `ca` | 赏金 |
| `ln` `sw` | 倾角 / 出拳动画进度 | `wb` | 车身晃动 |
| `nl` `nc` | 氮气中 / 氮气冷却剩余 | `sk` | 摔车原因（没摔就是空串） |
| `sm` | 体力 | | |

手里那几件家伙（**只有真的带着东西时才发这两个字段**——空手是最常见的状态，
十五台车每帧各背一个空数组纯属浪费）：

| 字段 | 含义 |
|---|---|
| `wp` | 腰里那串家伙，从**手里那件**开始按轮换顺序排：`[[id, 剩余次数], …]`，最多 4 件。`id` 见 `sim/weapons.mjs` 的八行表（`club`/`chain`/`nunchaku`/`crowbar`/`mace`/`prod`/`oilcan` 等），`剩余次数` 只有电棍/流星锤/油瓶有用，其余恒为 0 |
| `wi` | 上面那串里当前轮到第几件（`0` 就是"手里这件"）。0.5 秒冷却之外的换手动作由 `act` 的第 3 位驱动 |

地上的家伙走顶层 `pk`，定长数组 `[id, x, z, 剩余次数]`——和车流一样是**世界的东西**，
不属于任何人：谁先压上去谁捡走，摔车的人会把腰里那串撒回路面。

**只发给我自己**的那一条额外带（时间线对账的全部依据）：

| 字段 | 含义 |
|---|---|
| `ak` | 已被确认的命令序号 |
| `ax` `az` | 那条命令走完时的位置 |
| `av` | 那时的速度 |
| `alt` | 那时的侧滑量 |
| `q` | 队列里还剩几格（诊断用：延迟越高，预测领先越多） |

赛车比射击版多两个自由度（速度、侧滑）：只给坐标的话，从那个点重放出来的是一条
"直线往前跑"的假路径，一进弯整条路都错了。

车流 `tr[]` 是定长数组 `[id, kind, x, z, dir, state, y, spin, kmh, dmg]`：
`kind` 是 `car`/`pickup`/`van`/`truck`/`bus`/`container`/`tanker`/`mixer`/`tractor`/`trike`/
`police`/`oncom`/`dayun`（`oncom` 是迎面轿车、`police` 是警车、`dayun` 是大运，画法与
同向车不同：迎面看到的是大灯与风挡，而且迎面来的车必须点着大灯），
`dir` 是 1 同向 / -1 迎面，`state` 是 1 行驶 / 2 被踹飞（`y`/`spin` 就是飞起来的那两个动画量），
`dmg` 是它被踹瘪了多少（0~1，撞痕、塌角、碎风挡都由它驱动）。

事件 `ev[]` 只是**播报素材**（`k` 是类型，`i` 是行为主体），不参与判定：
判定早就发生在服务端的世界里了，客户端拿到的只是"该喊一声了"。

### `over` 里的 `results`

```json
{ "reason":"finish", "track":"city", "seed":113448647, "winner":"疤脸",
  "players":[ { "rank":1,"name":"疤脸","kind":"bot","time":76.15,"z":3600,
                "downs":3,"kills":1,"crashes":1,"cash":2750,"dnf":0 } ],
  "payout":{ "g_Fhog…":2750 } }
```

排名规则：冲过线的按**冲线时刻**排，没冲线的按**已跑距离**排，还没起跑的垫底；
`dnf: 1` 表示没跑完（结算页要能一眼看出"跑完的"和"被时间掐掉的"）。
赏金 = 名次底薪 + `downs × 250` + `kills × 1000`。`kills` 是这一局踹飞的社会车辆与
畜生的总数——十三种车、六种畜生，赏金按车重分档（三轮车 250、轿车 400、大运 1500）。

## 4. 改协议的三条规矩

1. **别改字段名**。客户端与 DO 是两个独立部署的产物，改名等于一次强制同时发布。
   加字段可以（老实现会忽略），改语义不行。
2. **身份只在名册里**。快照刻意不带 `ownerId`（15 台车每帧各背一个玩家 id 是纯浪费），
   查身份一律走 `wire.mjs` 的 `racerIdOf()` / `mineIn()`。忘了这一步的症状不是报错，
   而是**本地预测永不启动**——别人还在跑，只有你是块石头。
3. **`tm` 必须带毫秒精度**（`r3`）。`r1` 会把 6.94 秒记成 6.9，而快照每 50ms 一张，
   于是"两张快照的 `tm` 完全相同"和"差 100ms"会轮流出现——插值规则跳过前一对、
   又从后一对里一次性补回来，画面上就是**每 100ms 顿一下**。
