# 手感逐轮返工记

`feel.md` 讲的是这套手感**为什么是这样**（时间账、回看、判定窗、不变式）。这一份
记的是**每一轮线上反馈是怎么修掉的**：玩家原话、探针量到的数、根因、修法。

一版一轮，新的加在最后。每一轮的写法都一样：先给数字，再给根因，最后才是改了什么。

## 11. 路面上的车"一顿一顿"：抖的不是车流，是镜头

柠檬叔在第二台电脑上进来，说机器人的画面"卡的像幻灯片，根本不可玩"。查下去发现
跟网络没关系，也跟车流没关系——**车流的世界位置一直是平滑的，抖的是相机**。

账是这样的：本地预测（`predict.mjs`）是**整格**推进的，攒够 1/60 秒才走一格；
而相机严格贴着我这台车的 `z`（`road.mjs` 的 `createCamera`）。60fps 下"一帧一格"
刚刚好；120fps 变成"一格走两帧"，30fps 变成"一帧走两格"。于是**整幅画面**连同
路上所有的车一起，一格一跳。用假时钟量过（`tests/web-subtick.test.mjs`）：
120fps、37.8 m/s 时，我那台车逐帧位移的二阶差分是 **0.63 米**——一格一跳的台阶
就是这么大；社会车辆相对镜头同样是 0.64 米。

修法只有一句：**把"已经过去、还没来得及模拟"的那一小段时间补上**。`app.mjs`
每帧把攒在手里的 `state.acc` 留在 `S.tickAcc` 上，`view.mjs` 按 `v × tickAcc`
把我这台车往前推那半个格子。

两条边界值得单独记住：

- **补的是画面，不是世界**。预测状态一位都不许动——它动一点点，下一次对账
  （`reconcile`）就会把这几个厘米拽回去，画面反而更抖。测试里拿"关掉补帧的
  同一份代码"做对照，逐位比对预测状态。
- **车流也要补到同一个时刻**。`leadTime` 里那半格不能漏：漏了的话，我这一台
  比整条路超前最多一格，38 m/s 下就是 63 厘米——玩家看到的是"眼前那台车在抖"。

同一轮里两件小的，都是"设计做出来了，但玩家用不起来"的那一类：

**挥空要有回音。** 以前挥空只有一声很轻的响，玩家分不清"我打空了"、"我按了但
游戏没理我"、"我方向按反了"三件事。现在自己挥空会在拳够得到的那一截路上弹一个
`MISS`（前打摆身前、回身摆身后），方向对了但没打中一眼就看得出来。别人挥空一个字
都不弹——十五台车每次抡空都飘一行字，画面就成弹幕了。这个事件是 `sim/combat.mjs`
发的，车、牛、人三条路径共用同一次判定，所以字幕天生对三种目标一视同仁。

**名字牌回到头顶。** 原来挂在离地 2.9 米，而车手连人带盔才 1.84 米高——名字飘在
半空，和它下面那个人读起来是两件事。现在是 `render.mjs` 的 `NAME_H = 2.05`，
贴着盔顶一两指头。标签一旦和它的目标脱开，就不再是标签。

## 12. 怎么复测

```powershell
npm test                                          # 375 条，含 sim-laps / web-finishline / web-mouse-attack
                                                  #       / web-subtick / web-miss / web-nameplate
                                                  #       / web-camshake / web-hitmark / sim-kick-save
$env:E2E_PLAYWRIGHT_DIR='E:\dev-state\npm-global\node_modules'
npm run e2e                                       # 真浏览器、两个客户端；三圈的局要跑四分钟上下
```

手感本身要靠"灯驱探针"来量——它模拟一个**只看得懂 HUD 那两块牌子**的玩家：
牌子说「人 / 车 / 牛」就按 `J`，说「靠左 / 靠右」就压车，然后统计
「按下去的那些次里有多少真的打中了」。探针在 `.blacktop-scratch/`（不入库）。

| 探针 | 量什么 |
|---|---|
| `lampdrive.mjs` | 只看灯打的命中率、四种结果的分布、每一拳时画面与服务端的几何 |
| `qwatch.mjs` | 入力队列深度、RTT、预测与权威坐标的差、上行格数 |
| `flingscreen.mjs` | 被踹飞的车逐格落在**屏幕第几行第几列**（用渲染层那套相机） |
| `kicktrace.mjs` | 真游戏里逐帧记同一件事：赏金一跳就开始记，直到它烧完 |
| `kickprobe.mjs` | 纯模拟层：追着车跑的人被撞倒几次、踹飞几台（见第 13 节） |
| `artprobe.mjs` | 真浏览器里的画布：贴图有没有被切、星芒画不画得出来、震屏跳多大 |

**测出来的数才是结论。** 这一轮所有的修法都是先让探针跑出数字，再去改代码的——
改完再跑一遍同一支探针。没有数字的手感改动，就是在猜。

## 13. 「手感特么的不对劲」：卡、MISS、踢车、踢飞、命中

线上原话是一整段：「还是卡卡的…miss 的 m 和 s 好像被竖着切割了…我去踢车，经常
被车撞倒，很不爽…踢翻车，它还是经常向后方摔去，没有踢飞的实感…踢/打摩托车，
几乎无法踢翻对方，且就算踢到了，也没有视觉提醒。」五条症状，五个不同的根因。

### 13.1 「卡」不是帧率，是观感

先排除掉最像的那一个。真 Chrome 窗口里的探针：帧间隔 31 毫秒、每帧回调 4.5 毫秒
（p95 6.5）。无头 Chrome 的 31fps 是它自己的天花板——空白页对照同样是 32 毫秒。
**没有渲染瓶颈**。真凶是两个：

- **随机震屏**。原来是 `ctx.translate((Math.random() - .5) * shake, ...)`，混战里
  `shake` 常年挂在 7~14，也就是每一帧把整幅画随机挪 ±3.5~7 像素、还顺手随机拧一点
  角度。逐帧独立的位移在人眼里的名字不叫"震了一下"，叫**"这台机器在抖"**——随机
  噪声恰恰就是"卡顿"在视觉上的长相。换成同一相位下的正弦叠加
  （`web/js/camshake.mjs`，三个整数倍频保证绕回点接得上）。
- **频率太高**。第一版正弦取 52 rad/s，60 帧下每帧推进 0.87 弧度，二倍频分量
  （16 赫兹）于是每帧跳 5.5 像素——那不是"镜头被撞了一下"，那是振动，也就是同一
  个"卡"字。降到 34 rad/s（≈5.4 赫兹）之后，60 帧下相邻两帧最大跳 2.5 像素。

`tests/web-camshake.test.mjs` 把这条钉死，并且验的是"采样加密四倍、跳变跟着缩到
四分之一"——逐帧独立的随机数做不到这一条，它的跳变和采样率无关。

### 13.2 MISS 的 M 和 S 被竖着切

根因一句话：`labels.mjs` 的 `tile()` 量宽度时**从没设过字体**。`measureText` 量的
是 `ctx` **当前**那号字体，而画布刚建好时是 10px sans-serif——不管要烘多大的字，
量出来永远是"10 像素下的那一行"。贴图于是比字形窄一大截，`fillText` 画到画布外的
部分被边缘切掉，左右各少一块；字号越大切得越狠，而 MISS 是跳字里最大的那几个之一。

修法：量之前先把字体设成要烘的那一号（`measureWidth`，带 `save/restore`）。真浏览器
探针：MISS 的墨迹宽 153 像素，基准（真 `measureText`，143.7）的 1.06 倍——多出来的
那一点正是描边与留白；改之前这个比值是 0.36。

顺带把"容易忽略"也修了：跳字字号分四档（28 / 44 / 56 / **68**），MISS 独占最高的
那一档、挂 1.35 秒（普通跳字 1 秒），颜色提到最亮的一档白蓝。它不必比"赏金 +400"
热闹，但它绝不能被漏掉——漏掉一次，玩家就会以为"我按了，游戏没理我"。

### 13.3 踢车反被撞倒

判定本身没错：踹车的窗口几何上**完整地盖住**撞车窗口，同一格先跑 `attack` 再跑
`collideTraffic`，按得准从来救得了人。漏人的是两个缝：`aimAt` 里**畜生优先于车**
（那 0.42 秒的窗口被拿去踹牛了），以及车是在**手挥出去之后**才撞进来的。

修法是一条**直达**的保命窗（`sim/impact.mjs` 的 `kickSave`）：最近一次前打还在
`TUNE.atkSave = 0.22` 秒之内、横向在一整个车道之内、目标是可踹的车 → 撞车改判踹飞。
它不问牛、不问别人，只问"你刚才是不是冲着前面出拳了"。0.22 秒比 `atkWindow` 短、
也比 `attackCd` 短，所以按住 `J` 连打并不能让谁在车流里无敌。

模拟层探针（`kickprobe.mjs`，180 秒 × 3 个种子，每格重新决策）：

| 组 | 做法 | 踹飞 | 被撞倒 |
|---|---|---|---|
| A | 追着前面的车压过去 + 一直按 `J` | 20.8 台/分 | **0.89 次/分** |
| B | 同样追、一下都不打 | — | 11.89 次/分 |
| C | 同 A，但把保命窗关掉（这一轮之前） | 20.9 台/分 | 1.11 次/分 |

一句话：**会打的人被撞倒的次数，是只会撞的人的 7%**；保命窗再把"我明明按了却被
撞下来"的那几次救回两成。

（探针自己也踩了一个坑，记在这里：`tests/helpers.mjs` 的 `run()` 每格走完就清事件，
在它的 `each` 里读事件**永远是空的**——量化手感的脚本必须自己驱动 `stepWorld`。）

### 13.4 「踢飞了却向后摔」

被踹飞的车原来**顺着它自己原来的方向**继续跑：对向车本来就朝你冲，被踹了还朝你冲，
相对速度 70 m/s，0.15 秒滑出画面下缘，玩家只听见"砰"一声。现在一律朝路的正方向飞，
初速保证**比踹它的人快 7 m/s 以上**（慢一点就等于"等着被超越"），横向只给一条车道的
量，翻滚的初始角速度跟着横推方向定符号——从左边踹和从右边踹原来飞出来一模一样。
`tests/sim-fling-sight.test.mjs` 逐格量它相对玩家的 `dz`，钉住"一秒之内不许掉到身后
8 米、也不许窜到前面没影"。

### 13.5 打不翻 + 打实了没人回答

**伤害太软。** 一拳 17 + 速度×0.12（120 km/h 约 22 点）打满 100 点体力要五拳，而
相对速度决定你根本凑不满五拳。现在 28 + 速度×0.12，并且速度过 30 m/s（108 km/h）
额外加 12 点——"飞踢"和"停着抡"不该一个价。结果是低速三拳、高速两拳、手里拿着撬棍
低速两拳（`tests/sim-knockdown.test.mjs`）。

**打实了要有回答。** 以前只有火花和一个 `-数字`。现在三件套，而且全都是"给我看的"
（别人打别人一条都不发——十五台车每一下都炸一颗星，屏幕上就只剩星了）：

- 一颗美漫的星（`web/js/hitmark.mjs`）：三层同心星，踢车 1.5 份、大运 2.2 份；
- 一句拟声词（砰！咚！哐！嘭！啪！轮转，**不随机**：随机的拟声词会听成杂音）；
- 屏幕正中四道短斜线的准星回执（`web/js/overlays.mjs`），200 毫秒收掉，位置就在
  玩家出手时盯着的地方；挨打的那一方整车白闪 0.45 秒（`sprites.mjs` 的 `flash`）。

星芒的美术迭代了三版，每一版的毛病都记在文件头里：圆头射线那版读成**太阳**，锥形
短箭头那版读成**纸屑**，现在这一版是三层同心星（四角长爆 + 六角星体 + 白色内芯），
轮廓取的是**并集**（先整层粗描底、再用同色填回来）——每层各描一圈会画成一颗洋葱。
